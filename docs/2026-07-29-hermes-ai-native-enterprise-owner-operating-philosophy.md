## 1. 文档定位

本文件从老板和企业经营者的角度回答五个问题：

1. AI 时代，公司究竟是什么；
2. 老板还应该控制什么，应该把什么释放给员工和 Agent；
3. 外部营销增长与内部能力建设如何形成同一个经营闭环；
4. 组织如何从“人适应系统”转向“每个员工拥有自己的 AI 执行系统”；
5. Hermes 为什么不是另一个大一统数字化系统，而是 AI 原生组织的运行基础。

本文件既是内部经营纲领，也是对外商业理论。内部使用时，它负责统一老板和核心

## 2. 老板需要先改变的问题定义

### 2.1 旧问题

传统数字化通常把问题定义为：

- 需要建设哪些系统；
- 需要多少页面；
- 哪些流程要固化；
- 哪些员工必须填写哪些字段；
- 如何把所有工作装进统一平台；
- 如何让管理层看到更多数据；
- 如何减少人的自由裁量。

这种方式在流程稳定、变化缓慢、信息稀缺的阶段有效。但它也形成了长期成本：

- 每个部门建设自己的系统；
- 业务变化必须等待 IT 改页面；
- 员工在系统之间搬运数据；
- 经营逻辑散落在表格、制度、人的经验和代码中；
- 管理层看到越来越多报表，却不一定更快作出正确决策；
- 组织的真实能力被锁在少数员工和特定系统里；
- 系统记录动作，却不能解释为什么这样做；
- 数字化最终成为新的协调负担。

### 2.2 新问题

AI 原生企业应把问题改写为：

- 公司需要保留哪些权威事实；
- 公司真正依赖哪些经营杠杆；
- 哪些能力可以被表达、验证和复用；
- 哪些决策必须由人承担责任；
- 哪些执行可以交给员工自己的 Agent；
- 如何让一次正确实践成为全公司的下一次能力；
- 如何在不建设更多固定页面的前提下完成更多业务；
- 如何让组织学习速度持续高于竞争对手。

老板不再以“建设多少系统”衡量数字化，而以“形成多少可复用经营能力、减少多少
协调摩擦、缩短多少经营反馈周期”衡量组织进化。

## 3. 对未来企业的基本判断

### 3.1 企业不会消失，企业的协调方式会改变

企业存在的原因之一，是以组织方式完成市场上难以低成本协调的复杂活动。AI 不会
消除目标冲突、资本约束、责任、风险和客户承诺，但会显著降低以下成本：

- 信息搜索；
- 内容生成；
- 数据整理；
- 规则执行；
- 多系统操作；
- 标准任务协同；
- 经验复制；
- 过程追踪；
- 状态汇总。

因此，未来企业不是没有管理，而是管理重心从“逐步监督执行”转向：

- 设定方向；
- 选择经营杠杆；
- 定义边界；
- 分配资源；
- 规定责任；
- 验证结果；
- 处理例外；
- 进化组织能力。

### 3.2 AI 的价值不等于个人使用量

员工多使用几次 AI，不等于公司完成 AI 化。真正的企业价值来自：

1. AI 进入正式工作流；
2. 工作流产生可验证结果；
3. 结果形成证据；
4. 证据沉淀为知识和 Skill；
5. Skill 被更多员工和 Agent 复用；
6. 组织根据效果调整规则和资源；
7. 能力迭代速度持续提高。

[OpenAI 2025 企业 AI 报告](https://openai.com/business/guides-and-resources/the-state-of-enterprise-ai-2025-report/)
显示，企业使用正在从临时问答转向可重复的项目、定制能力和多步骤工作流。该趋势
支持“AI 从工具变为组织基础设施”的方向，但 Hermes 仍以客户经营结果而不是消息
数量判断价值。

### 3.3 组织结构比模型能力更可能成为瓶颈

[Microsoft 2026 Work Trend Index](https://news.microsoft.com/annual-work-trend-index-2026/)
将 AI 协作区分为辅助、编辑、任务导演和多 Agent 编排，并把经营模型重构视为领导
者的核心工作。

[McKinsey 2025 全球 AI 调研](https://www.mckinsey.com/capabilities/quantumblack/our-insights/the-state-of-ai-how-organizations-are-rewiring-to-capture-value)
指出，工作流重设计与生成式 AI 的经营影响高度相关。该研究同时表明，治理、领导
参与、培训、信任和反馈机制不能被模型采购替代。

### 3.4 必须保持战略克制

[Stanford 2026 AI Index](https://hai.stanford.edu/ai-index/2026-ai-index-report)
显示企业 AI 采用继续扩大，但宏观层面的生产率证据仍在形成，收益分布也不均衡。

因此，老板不能因为技术进步就假设：

- 所有流程都应自动化；
- 所有岗位都应立即改变；
- 所有 AI 输出都能转化为利润；
- 模型越强，组织价值越大；
- AI 采用率越高，经营越成熟；
- 大量建设 Agent 就会自然形成组织能力。

AI 原生经营必须以利润、现金、客户结果、风险和组织能力复用进行验证。

## 4. AI 时代的企业本质

### 4.1 公司不是系统集合

公司表面上由部门、岗位、系统和流程组成，本质上由以下对象构成：

```text
共同目标
  + 客户价值
  + 资本和资源
  + 权威事实
  + 经营规则
  + 组织责任
  + 协作网络
  + 可复用能力
  + 风险边界
  + 持续学习
```

系统只是承载这些对象的工具。系统不能成为公司本身，也不能因为系统已经建设而
阻止组织采用更好的执行方式。

### 4.2 公司是能力复利机器

AI 原生企业的长期竞争力可以用一个理论表达式描述：

```text
Enterprise Intelligence(t+1)
  = Enterprise Intelligence(t)
  + Validated Experience
      × Reusability
      × Distribution
      × Adoption Quality
  - Knowledge Decay
  - Coordination Friction
  - Risk Loss
```

该表达式不是财务会计公式，而是经营判断框架：

- 只有经过结果验证的经验才增加企业智能；
- 经验不能复用，就只是个人生产力；
- 能力不能分发，就不能形成组织杠杆；
- 被使用但结果无效，不形成真实复利；
- 知识过期和规则失效会消耗组织能力；
- 协调成本过高会抵消 AI 带来的执行效率；
- 越权、错误承诺和错误自动化会产生风险损失。

### 4.3 组织能力的最小单元

未来企业能力不再以“一个系统模块”作为最小单元，而以以下对象组合：

```text
Business Object
  + Data Product
  + Metric
  + Knowledge Asset
  + Action
  + Skill
  + Task Contract
  + Policy
  + Evidence
```

这些对象可以被员工 Agent 动态组合。页面和组织界面可以变化，经营事实、权限、
责任和结果标准保持稳定。

## 5. 双层 ILPO：从经营选择到 Agent 执行

### 5.1 两套 ILPO

公司保留两套 ILPO：

| 层级 | I | L | P | O | 责任主体 |
|---|---|---|---|---|---|
| 业务 ILPO | Insight | Leverage | Process | Output | 老板、经营 Owner、人机共同判断 |
| 执行 ILPO | Input | Logic | Process | Output | 员工 Work Agent 主执行、员工负责 |

业务 ILPO 回答：

- 我们看见了什么；
- 哪个杠杆值得投入；
- 需要组织怎样的经营过程；
- 结果和边界是什么。

执行 ILPO 回答：

- 本次任务使用哪些输入；
- 使用哪些逻辑、规则和约束；
- 由人、Agent、系统如何执行；
- 输出如何确认、回写、撤销和复盘。

### 5.2 Task Contract 是两层之间的正式交接

```text
Business ILPO
  -> Task Contract
  -> Execution ILPO
  -> Outcome / Evidence
  -> Business ILPO Review
```

Task Contract 不是一段任务描述，而是经营主权向执行系统授权的契约。至少定义：

- 业务目标；
- 经营场景；
- 输入事实和版本；
- 可使用的逻辑；
- 风险约束；
- 输出等级；
- Owner；
- 人工确认路线；
- 写回对象；
- 停用条件；
- 撤销规则；
- 追溯 ID；
- 价值指标。

### 5.3 “把 ILPO 交给员工自己的 AI”应该如何理解

正确的理解不是把全部经营判断交给 AI，而是：

1. 老板和经营 Owner 保留 Business ILPO 的最终主权；
2. AI 可以帮助发现 Insight、模拟 Leverage 和设计 Process；
3. Business ILPO 经人确认后形成 Task Contract；
4. 每个员工的 Work Agent 负责执行 Execution ILPO；
5. 员工对目标、确认、承诺和结果负责；
6. Evolution Agent 从结果中提出能力改进；
7. 企业通过新一轮 Business ILPO 决定是否扩围。

这形成：

> 人类主导经营选择，Agent 主导受控执行，组织依据结果持续进化。

### 5.4 ILPO 不再困在大一统系统中

传统系统把执行 ILPO 固化在：

- 固定页面；
- 固定按钮；
- 固定审批流；
- 固定角色；
- 固定报表；
- 固定模块边界；
- 无法解释的代码逻辑。

当业务变化时，企业必须重新开发系统。员工只能适应系统，不能围绕工作目标组织
自己的执行方式。

Hermes 的改变是：

```text
企业中央保留：
事实、语义、身份、权限、Policy、Action、Skill、Evidence

员工边缘拥有：
自己的 Work Agent、个人 View、任务上下文、受控执行和协作方式
```

中央系统从“大一统业务界面”收缩为“共同经营宪法和能力基础设施”；员工 Agent
成为分布式执行运行时。

### 5.5 中央薄治理，边缘厚智能

这一组织原则可以概括为：

```text
中央薄治理
  = 目标、事实、口径、权限、红线、资本、责任、审计

边缘厚智能
  = 员工判断、Agent 规划、动态页面、任务执行、协作、反馈
```

“薄”不代表治理弱，而是中央不再预先规定每一个页面和每一步操作。“厚”不代表
员工可以越权，而是允许员工和 Agent 在明确契约内选择更好的执行路径。

## 6. 老板经营心智的十二个转变

| 旧心智 | 新心智 |
|---|---|
| 建系统 | 建事实、契约和能力 |
| 管页面 | 管目标、边界和结果 |
| 人适应流程 | Agent 围绕任务组织流程 |
| 信息越集中越好 | 事实统一、执行分布 |
| 经验属于岗位 | 经验证经验属于组织资产 |
| 自动化等于少用人 | 自动化用于扩大能力和经营半径 |
| 部门拥有数据 | 企业拥有事实，Owner 承担治理责任 |
| 管理靠过程可见 | 管理靠结果、证据和例外 |
| AI 是软件采购 | AI 是组织运行能力 |
| 使用量代表采用 | 有效 Outcome 代表采用 |
| 老板作出所有判断 | 老板设计判断和升级机制 |
| 竞争优势来自模型 | 竞争优势来自能力复利速度 |

### 6.1 老板不能下放的责任

- 企业使命和价值选择；
- 战略方向；
- 资本配置；
- 经营红线；
- 重大杠杆选择；
- 品牌承诺；
- 客户和社会责任；
- 关键人才和组织结构；
- 高风险授权；
- 最终经营结果。

### 6.2 老板应该释放的执行

- 数据收集和整理；
- 标准分析；
- 多方案模拟；
- 重复协同；
- 规则校验；
- 状态跟进；
- 正式信息汇总；
- 低风险动作；
- 知识提取；
- 能力候选发现。

老板的价值不再是比所有员工更忙，而是让组织在自己不直接参与每一步的情况下，
仍然按照正确目标、规则和反馈持续运行。

## 7. 内外一体的经营模型

### 7.1 外部增长与内部能力不是两套系统

企业经营有两个飞轮：

```text
外部增长飞轮：
市场信号
  -> 客户洞察
  -> 价值主张
  -> 产品和内容
  -> 渠道与销售
  -> 交付与服务
  -> 收入、毛利、现金和客户资产

内部能力飞轮：
工作任务
  -> Outcome
  -> Evidence
  -> Knowledge
  -> Skill
  -> Agent 执行
  -> 更高质量 Outcome
```

两个飞轮通过客户结果和经营事实连接：

- 外部经营为内部学习提供真实结果；
- 内部能力降低下一次增长成本；
- 营销经验沉淀为企业 Skill；
- 服务问题反向改进产品和营销；
- 财务结果约束增长质量；
- 组织能力决定增长是否可以复制。

### 7.2 经营闭环

```text
Strategy
  -> Business ILPO
  -> Task Contract
  -> Employee Work Agent
  -> Agent Collaboration
  -> Action / Delivery
  -> Customer & Business Outcome
  -> Evidence
  -> Knowledge / Skill
  -> Evolution Agent
  -> Business ILPO Review
```

一个经营动作只有回到这个闭环，才是组织 AI 化的一部分。

## 8. 外部增长：AI 时代的营销本质

### 8.1 营销不是内容产量

AI 可以让内容供给大幅增加，但内容数量不是增长。营销的本质仍然是：

- 识别真实需求；
- 选择目标客户；
- 建立差异化价值；
- 形成可信承诺；
- 在正确渠道触达；
- 促成交易；
- 交付客户结果；
- 建立长期关系；
- 获得可持续利润和现金。

如果没有客户、产品和渠道事实，AI 只会扩大低质量内容。

### 8.2 营销业务 ILPO

| ILPO | 营销经营问题 | 典型对象 |
|---|---|---|
| Insight | 客户为什么购买、拒绝、流失和复购 | VOC、搜索、销售对话、工单、订单 |
| Leverage | 产品、品牌、价格、内容、渠道和关系中哪个杠杆有效 | Product、Offer、Channel、Audience |
| Process | 如何实验、触达、转化、交付和复盘 | Campaign、Lead、Opportunity、Service |
| Output | 是否形成有利润的增长和客户资产 | Revenue、Margin、Cash、Retention、Trust |

### 8.3 营销执行 ILPO

员工 Work Agent 把营销 Task Contract 转换为：

| ILPO | 执行内容 |
|---|---|
| Input | 客户分层、产品事实、库存、价格、品牌规范、渠道规则 |
| Logic | 投放阈值、内容规则、毛利底线、触达频率、合规要求 |
| Process | 研究、创作、审核、发布、线索处理、销售协同、服务回收 |
| Output | 内容、活动、线索、订单、客户反馈、复盘和 Skill 候选 |

### 8.4 营销工作流

```text
市场信号
  -> Insight Candidate
  -> 人工确认客户问题
  -> 价值假设
  -> 实验 Task Contract
  -> 内容 / 渠道 / 销售 Agent 协作
  -> 小范围发布
  -> 转化和交付
  -> 毛利、现金、留存和信任评估
  -> 赢单 / 失单 Evidence
  -> 营销知识与 Skill
```

### 8.5 从 Campaign 经营转向持续感知

传统营销以活动为中心，开始和结束都很清楚；AI 原生营销更接近持续系统：

- 持续收集授权市场信号；
- 持续更新客户问题和机会假设；
- 持续生成并验证内容变体；
- 持续把销售和服务反馈回写；
- 持续淘汰无效内容和渠道；
- 持续更新品牌、产品和渠道 Skill。

持续不等于无限自动发布。品牌承诺、价格、客户敏感沟通和高风险内容仍需要人工
Owner。

### 8.6 DTC+：“强品牌、全渠道”的增长操作系统

本文件吸收 DTC+ 渠道力理念，但不把 DTC+ 定义为一个独立站项目。Hermes 中的
DTC+ 是：

```text
直接客户关系和客户事实
  + 强品牌
  + 创作者传播生态
  + 产品与内容营销
  + 电商增长变现
  + 线下零售
  + 数字驱动
  + 客户复购
```

DTC 官网只是一个渠道。DTC+ 的核心是企业能否跨平台持续识别客户、理解客户、
兑现承诺并形成复购，而不是企业是否拥有一个网站。

### 8.7 DTC+ 的四个经营域

| 经营域 | 作用 | 典型能力 |
|---|---|---|
| 传播创作者生态 | 让市场知道、理解并相信品牌 | 达人、用户内容、本地化内容和社媒 |
| 产品及内容营销 | 把正确产品和内容送到正确人群 | 站外、站内、DSP、开放互联网广告 |
| 电商增长变现 | 把兴趣转为交易、服务和复购 | Marketplace、Social Commerce、DTC |
| 线下零售 | 扩大触达、信任和购买便利 | 零售合作、门店、陈列和渠道扩展 |

四个经营域不能由四个部门独立优化。它们必须共享客户、产品、内容、库存、价格、
渠道、订单、利润和 Evidence。

### 8.8 传播创作者生态

传播创作者生态包括：

- 海外红人和达人营销；
- 本土化品牌文案；
- 海外品牌视觉塑造；
- 海外社交媒体运营；
- 本土化视频创意与拍摄；
- 用户内容收集与授权；
- 创作者关系和长期合作；
- 不同市场的文化与合规适配。

企业不应只购买单次发帖，而应管理完整 Creator Lifecycle：

```text
Creator Discovery
  -> Audience & Brand Fit
  -> Brief
  -> Contract / Rights
  -> Content Production
  -> Review
  -> Publish
  -> Engagement / Conversion
  -> Customer Outcome
  -> Creator Evaluation
  -> Reuse / Stop
```

### 8.9 产品及内容营销

产品及内容营销覆盖：

- 站外广告；
- Marketplace 站内广告；
- Retail Media；
- DSP；
- Open Internet；
- 搜索；
- 社交平台；
- 再营销；
- 品牌内容；
- 商品内容；
- 促销内容；
- 客户教育内容。

广告 Agent 不能只优化点击和平台 ROAS。必须同时读取：

- 产品毛利；
- 库存和在途；
- 退货和质量；
- 客户生命周期；
- 渠道费用；
- 品牌规范；
- 现金预算；
- 履约能力。

### 8.10 电商增长变现

电商域包括：

- Amazon 等 Marketplace 运营；
- TikTok Shop 等 Social Commerce；
- DTC 官网；
- 商品上架；
- 价格和促销；
- 库存分配；
- 订单和履约；
- 客服；
- 评论和 VOC；
- 复购；
- 会员和生命周期经营。

电商不是营销活动的最后一个按钮，而是客户承诺兑现和经营结果确认的位置。

### 8.11 线下零售

线下零售包括：

- 零售商合作；
- 渠道准入；
- 门店和区域扩展；
- 采购和补货；
- 陈列和促销；
- Retail Media；
- 门店库存；
- Sell-in 与 Sell-through；
- 渠道账单；
- 退货和损耗；
- 线上线下客户反馈。

Walmart、Target、Home Depot、Best Buy 等大零售商只是渠道示例。Hermes 不把
某个零售商写入核心契约，而使用 `retail_partner`、`store`、`retail_order`、
`retail_inventory` 和 `retail_settlement` 等通用对象。

### 8.12 数字驱动的闭环

图中的“数字驱动”在 Hermes 中不是建设更多营销报表，而是建立统一经营事实：

```text
Creator / Content / Ad / Channel
  -> Customer Signal
  -> Visit / Engagement
  -> Lead / Cart / Order
  -> Delivery / Return / Service
  -> Revenue / Margin / Cash
  -> Repurchase / Churn
  -> Evidence
  -> 下一轮 Insight 与 Leverage
```

每个经营对象必须通过可追溯 ID 连接到后续 Outcome。无法连接到客户、订单、毛利、
现金或有效品牌结果的活动只能被视为探索性投入。

### 8.13 用户复购是 DTC+ 的中心结果

获客只能证明企业获得一次机会，复购才开始证明：

- 产品价值成立；
- 品牌承诺被兑现；
- 交付和服务可接受；
- 客户关系可以积累；
- 获客成本有机会被摊薄；
- DTC 客户资产正在形成。

DTC+ 不应把复购简化为再次推送促销。复购经营包括：

- 产品使用周期；
- 补充和替换周期；
- 客户满意；
- 质量和退货；
- 售后服务；
- 内容教育；
- 新产品关联；
- 频率控制；
- 客户授权；
- 长期价值和毛利。

### 8.14 DTC+ 成熟度

结合图中的 L2/L2++ 复购和 L4 精准营销，本文件定义：

| 等级 | 主要能力 | 经营状态 |
|---|---|---|
| L0 渠道存在 | 开账号、上架、发布内容 | 有渠道，没有闭环 |
| L1 运营协同 | 内容、广告和电商基础运营 | 能获得流量和订单 |
| L2 交易复购 | 订单、服务和复购可识别 | 开始形成客户生命周期 |
| L2++ 客户资产 | 跨渠道客户事实和复购运营 | DTC 关系不再依赖单一平台 |
| L3 全渠道协同 | 创作者、广告、电商和零售共享事实 | 可以按客户和产品协调资源 |
| L4 精准经营 | 数据、AI 和 Agent 按 Outcome 动态编排 | 实现人群、内容、产品、渠道和时机匹配 |

L4 不是“广告定向更细”，而是：

- Insight 来自真实客户和经营事实；
- Leverage 可以跨品牌、产品、渠道和内容选择；
- Process 由员工 Agent 动态协同；
- Output 同时满足收入、利润、现金、复购和品牌约束。

### 8.15 DTC+ 业务 ILPO

| ILPO | DTC+ 经营定义 | 老板和 Owner 的责任 |
|---|---|---|
| Insight | 客户、市场、产品、渠道和内容的真实变化 | 判断哪些变化值得相信 |
| Leverage | 品牌、产品、价格、Creator、内容、广告、渠道和零售 | 选择资源投入杠杆 |
| Process | 研究、创作、投放、交易、履约、服务和复盘 | 定义跨域过程和责任 |
| Output | 收入、毛利、现金、复购、客户资产和品牌信任 | 确认结果和是否扩围 |

### 8.16 DTC+ 执行 ILPO

| ILPO | 员工 Work Agent 的执行内容 |
|---|---|
| Input | Product、Audience、Creator、Content、Inventory、Price、Channel、Budget、Order、VOC |
| Logic | 品牌规范、毛利底线、库存约束、内容权利、频控、渠道政策和合规 |
| Process | Creator、Content、Media、Commerce、Retail、Service、Finance Agent 协作 |
| Output | Brief、Creative、Campaign、Listing、Order、Service、Repurchase、Evidence、Skill Candidate |

Business ILPO 通过 DTC+ Task Contract 下发，员工 Agent 不自行改变预算、品牌承诺、
客户授权和利润红线。

### 8.17 KOL、KOC、KOS、KOA 的角色体系

本文件将图中的四类角色作为 DTC+ 内部运营角色，不视为所有行业通用术语：

| 角色 | 核心任务 | 主要结果 |
|---|---|---|
| KOL | 让目标人群知道品牌和形成话题 | Reach、Brand Search、Qualified Attention |
| KOC | 以真实使用体验建立信任 | Trust、Review Quality、Consideration |
| KOS | 以销售和场景能力促成购买 | Qualified Conversion、Order、Margin |
| KOA | AI 数字创作者，规模化生成和适配内容 | Content Variant、Coverage、Response Speed |

四类角色不是线性漏斗，也不是互相替代：

- KOL 提供注意力和社会证明；
- KOC 提供真实体验和同伴信任；
- KOS 把产品价值转化为购买理由；
- KOA 扩展创意供给、语言、格式、时间和渠道适配。

### 8.18 KOA 的正确边界

图中“无限量产出内容、全天候承接流量”表达了 AI 的规模优势，但企业不能把它
直接作为生产目标。Hermes 将 KOA 定义为：

> 在品牌、事实、知识产权、渠道、预算和人工确认边界内持续生成、适配、测试和
> 回收内容的 AI 数字创作者。

KOA 可以：

- 将已批准核心创意适配为不同语言和比例；
- 根据渠道格式生成变体；
- 提取产品和客户 Evidence；
- 生成 A/B 测试候选；
- 在授权知识范围内回答标准问题；
- 将流量路由到合适内容、商品和人工；
- 识别高风险、敏感和无证据问题并升级。

KOA 不可以：

- 编造产品能力和客户评价；
- 无限制发布内容；
- 复制未授权创作者作品；
- 擅自使用人物肖像和声音；
- 绕过品牌和法务审核；
- 擅自改变价格、促销和库存承诺；
- 用私人数据进行定向；
- 在高风险客户沟通中替企业作承诺。

### 8.19 KOL/KOC/KOS/KOA 的 Agent 协作

```text
Brand Owner
  -> Campaign Task Contract

Creator Agent
  -> KOL / KOC 筛选、Brief 和权利

KOA
  -> 内容草案、本地化和渠道适配

Brand / Legal Human Gate
  -> 事实、品牌、版权和合规确认

Media Agent
  -> 站内、站外、DSP 和 Open Internet 投放

KOS / Sales Agent
  -> 场景解释、购买引导和异议处理

Commerce / Retail Agent
  -> 库存、交易、履约和渠道协调

Service Agent
  -> 客户结果、问题和复购

Finance Agent
  -> 毛利、现金和渠道费用

Evolution Agent
  -> Evidence、知识、Skill 和停用建议
```

这些 Agent 使用员工身份和 Task Contract 横向协作，不由一个中央营销 Agent
无边界控制所有渠道。

### 8.23 Attribution 原则

DTC+ 不以单一平台归因作为经营事实。至少区分：

- 平台报告归因；
- 企业订单和客户事实；
- Incrementality 实验；
- Cohort 复购；
- 品牌搜索和直接流量；
- 零售 Sell-through；
- 服务和退货；
- 财务毛利和现金。

不同 Attribution 结果发生冲突时，不能让 Agent 自动选择对本部门最有利的口径。
Metric Owner 定义正式使用场景和优先级。

### 8.24 全渠道而非渠道大一统

“全渠道”不意味着所有渠道使用相同内容、价格和动作，而是：

- 客户承诺一致；
- 品牌事实一致；
- 产品和库存事实一致；
- 渠道角色清楚；
- 数据可以解释差异；
- Outcome 可以比较；
- 客户可以顺畅迁移；
- 组织可以在渠道之间重新配置资源。

Marketplace、Social Commerce、DTC 和线下零售保留各自规则与优势。Hermes 统一
契约和经营事实，不强行统一渠道运营细节。

### 8.25 老板的 DTC+ 门禁

老板和经营 Owner 在扩张渠道前必须确认：

1. 目标客户和问题是否明确；
2. 品牌和产品 Claim 是否有证据；
3. 渠道角色是否清楚；
4. 库存、履约和服务能否支持增长；
5. 收入能否转化为毛利和现金；
6. Creator 内容权利是否完整；
7. 客户数据使用是否合法透明；
8. KOA 和自动化内容是否有人工门禁；
9. 渠道冲突如何处理；
10. 复购和客户资产如何沉淀；
11. 无效活动如何停止；
12. 结果如何形成 Evidence 和 Skill。

## 9. 营销增长与客户资产

### 9.1 客户不是流量记录

企业应建设客户事实，而不是只建设点击和线索：

- 客户身份和组织关系；
- 客户问题；
- 使用场景；
- 购买动机；
- 反对理由；
- 决策角色；
- 承诺和交付；
- 服务结果；
- 满意和流失原因；
- 允许使用的数据和联系方式。

### 9.2 客户资产的形成

```text
一次互动
  -> Customer Evidence
  -> 经过授权的客户事实
  -> 客户问题和决策模式
  -> 可复用 Offer / Content / Sales Skill
  -> 更准确的下一次互动
```

客户资产不等于无限收集个人数据。企业只应处理明确目的所需的数据，并保持授权、
用途、保留和删除边界。

### 9.3 品牌是 AI 时代的约束和杠杆

AI 降低内容生产成本后，品牌的价值不会下降，反而成为限制低质量自动生成和维持
一致承诺的重要基础。

品牌应被表达为：

- 客户价值承诺；
- 不做什么；
- 语气和表达；
- 事实和证据要求；
- 内容禁区；
- 价格和渠道原则；
- 客户权益；
- 危机升级路线；
- 人工确认边界。

品牌规范进入 Skill 和 Policy，但品牌最终主权属于企业和品牌 Owner。

## 10. 内部驱动：组织为什么愿意持续进化

### 10.1 内驱不来自监控

通过屏幕、键盘、在线时长和消息数量监控员工，可能提高短期服从，却会破坏：

- 主动性；
- 信任；
- 创造力；
- 知识贡献；
- 对结果的责任感；
- 对 AI 系统的真实反馈。

AI 原生组织的内部驱动来自：

```text
目标清楚
  + 权限清楚
  + 资源可得
  + 反馈及时
  + 贡献可见
  + 成长可见
  + 结果负责
  + 低价值摩擦减少
```

### 10.2 员工从系统操作员转为结果 Owner

传统数字化把员工变成：

- 字段填写者；
- 数据搬运者；
- 系统切换者；
- 流程等待者；
- 报表生产者。

Work Agent 承担这些机械执行后，员工的核心工作转向：

- 设定目标；
- 判断上下文；
- 选择标准；
- 验证结果；
- 处理例外；
- 建立关系；
- 作出承诺；
- 贡献组织能力。

### 10.3 员工自己的 AI 是个人经营运行时

每个员工的 Work Agent 应理解：

- 该员工承担的目标；
- 当前 Work Item；
- 可访问的数据；
- 已授权 Skill；
- 团队约定；
- 企业政策；
- 需要本人确认的事项；
- 个人保存的工作偏好。

Work Agent 不拥有员工私人生活，不替员工承担责任，也不把 Personal Memory 自动
转化为企业资产。

### 10.4 内部驱动的正循环

```text
员工获得更强执行能力
  -> 可以承担更大目标
  -> 结果和贡献更清晰
  -> 有效方法形成候选
  -> 员工参与确认和优化
  -> 公司 Skill 提升
  -> 员工获得更强能力
```

企业激励的重点应从“是否按旧流程工作”转向：

- 是否产生有效 Outcome；
- 是否减少长期摩擦；
- 是否贡献可复用资产；
- 是否发现和修正规则错误；
- 是否帮助团队形成更高能力；
- 是否承担并完成更高价值目标。

## 11. 组织 AI 化的五个阶段

### Level 1：工具化

员工使用 AI 写作、搜索、翻译和分析。

特征：

- 价值主要属于个人；
- 结果难追溯；
- 经验不复用；
- 公司无法判断真实 ROI。

### Level 2：工作流化

AI 进入重复工作流，使用模板、知识和工具。

特征：

- 任务开始可重复；
- 输入输出开始结构化；
- 仍然依赖单个部门和项目。

### Level 3：能力化

工作流被封装为 Data Product、Action 和 Skill。

特征：

- 有 Owner、版本、评估和权限；
- 能力可以跨团队复用；
- 结果可以回写和复盘。

### Level 4：组织化

员工 Work Agent 横向协作，Evolution Agent 纵向沉淀能力。

特征：

- Task Contract 成为正式交接；
- 人和 Agent 形成协作网络；
- 组织按结果、例外和能力运营；
- 固定业务页面开始减少。

### Level 5：经营模式化

AI 能力影响产品、营销、组织和商业模式。

特征：

- 市场响应速度形成竞争优势；
- 企业能力可以快速复制到新团队和新市场；
- 人均经营半径扩大；
- 新业务的边际组织成本下降；
- 公司成为持续学习和能力复利系统。

### 11.1 不能跨级建设

企业不能在没有数据、权限、Task Contract、Evidence 和 Skill 治理时直接宣布进入
Level 4 或 Level 5。否则只是把无边界的 AI 使用包装成组织转型。

## 12. AI 原生组织结构

### 12.1 三层组织

```text
经营层
  -> 定义 Business ILPO、资本、红线和结果

能力平台层
  -> 管理数据、Policy、Action、Skill、模型和治理

业务单元与员工层
  -> 使用 Work Agent 执行 Task Contract、服务客户和产生结果
```

### 12.2 经营层职责

- 选择市场和客户；
- 定义价值主张；
- 选择关键杠杆；
- 分配资本和人才；
- 定义结果与风险红线；
- 裁决跨域冲突；
- 决定哪些能力进入公司标准；
- 决定停止哪些业务、流程和 Skill。

### 12.3 能力平台层职责

- 企业身份和权限；
- Business Object 和 Data Product；
- Metric Registry；
- Knowledge Asset；
- Action 和 Skill；
- Model Gateway；
- Agent Ops；
- Evaluation；
- 安全、审计和员工透明度；
- 私有化和交付能力。

能力平台层不是新的中央业务部门，不能代替业务 Owner 定义客户价值和经营结果。

### 12.4 业务单元职责

- 对客户和经营结果负责；
- 把目标转为 Task Contract；
- 使用员工 Work Agent；
- 处理例外和承诺；
- 验证 AI 结果；
- 提交 Evidence；
- 贡献知识和 Skill 候选；
- 对无效能力提出停用。

## 13. 双层 Agent 与组织进化

### 13.1 Work Agent：分布式执行

Work Agent 服务具体员工和具体经营任务：

- 理解目标；
- 装配受权上下文；
- 执行 Execution ILPO；
- 生成动态工作界面；
- 调用 Data、Knowledge、Action 和 Skill；
- 与其他员工及其 Agent 协作；
- 请求人工确认；
- 形成 Outcome 和 Evidence；
- 支持员工接管。

### 13.2 Evolution Agent：企业能力进化

Evolution Agent 服务企业能力体系：

- 发现重复工作；
- 识别知识缺口；
- 发现跨团队共性；
- 提出 Data Product、View 和 Skill 候选；
- 组织评估；
- 分析版本效果；
- 提出扩围、降级、回滚和停用建议。

Evolution Agent 不拥有企业能力直接发布权，也不依据员工活动数量作人事判断。

### 13.3 横向和纵向同时运行

```text
横向：
员工 A + Agent A
  <-> Work Item / Collaboration
员工 B + Agent B
  <-> 客户、供应商和其他团队

纵向：
Outcome / Evidence
  -> Knowledge Candidate
  -> Skill Candidate
  -> Evaluation / Approval
  -> Company Capability
  -> 所有有权 Work Agent
```

横向协作完成经营，纵向进化形成能力复利。

### 13.4 不建设一个全知全能的企业 Agent

一个拥有全公司数据、替所有人作判断的“超级 Agent”会带来：

- 权限集中；
- 单点错误；
- 业务上下文丢失；
- 责任模糊；
- 员工抵触；
- 模型和供应商锁定；
- 无法在私有化环境中灵活部署。

Hermes 采用同一内核、不同身份、不同范围的 Agent 网络。企业统一治理协议和能力，
不统一所有具体判断。

## 14. 组织权力、责任与 AI

### 14.1 AI 不能消灭组织主权

以下事项不能由 AI 单独决定：

- 企业战略；
- 预算和资本配置；
- 人事任免和薪酬；
- 重大客户承诺；
- 合同、付款和法律责任；
- 品牌立场；
- 高风险生产变更；
- 权限扩大；
- 经营损失责任；
- 规则和 Policy 正式发布。

### 14.2 输出等级

AI 输出按影响分级：

| 等级 | 能力 | 组织要求 |
|---|---|---|
| A0 | 查询、整理、参考 | 不触发正式动作 |
| A1 | 解释、归因草案、事实缺口 | Owner 确认后进入复盘 |
| A2 | 方案、Action 草案、风险提示 | 主责岗位确认 |
| A3 | Rule Patch、参数和回写草案 | 多 Owner 确认后由授权系统执行 |
| A4 | 阻断、停用和撤销建议 | 授权岗位裁决 |

AI 不直接生效价格、预算、采购、付款、权限、人事、合规和对外承诺。

### 14.3 管理者的角色变化

管理者从任务分发者转向：

- 目标定义者；
- 优先级裁决者；
- 资源配置者；
- 例外处理者；
- 结果验证者；
- 人才发展者；
- Skill Owner；
- 组织学习推动者。

管理层如果仍然要求逐级汇报每个动作，就无法获得 Agent 带来的组织速度。

### 14.4 员工的权利

组织 AI 化必须保证员工：

- 知道采集什么；
- 知道用于什么；
- 能查看访问记录；
- 能纠正错误；
- 能接管 Agent；
- 能撤销个人委托；
- 能对候选知识提出异议；
- 不因提示词、在线时间和消息数量被排名；
- 不因 AI 单一判断承担人事结果。

信任不是文化口号，而是组织 AI 系统的运行条件。

## 15. 老板的经营节奏

### 15.1 每日：只看例外和现金影响

老板每日不应查看全部员工活动，而应查看：

- 现金和重大资金变化；
- 经营红线；
- 客户重大承诺；
- 交付阻塞；
- 品牌和合规风险；
- 高影响异常；
- 需要老板裁决的跨域冲突；
- 被 Agent 自动停止的高风险能力。

### 15.2 每周：经营闭环

每周经营会按 Business ILPO：

| 环节 | 核心问题 | 输出 |
|---|---|---|
| Insight | 本周有什么新事实改变判断 | Insight Card |
| Leverage | 当前最值得投入的杠杆是什么 | Leverage Decision |
| Process | 哪些跨域过程需要调整 | Task Contract / Action |
| Output | 结果、偏差和下一步是什么 | Outcome / Evidence |

会议不要求部门重新制作大量 PPT。事实、指标、Work Item 和 Evidence 应由经营
系统自动组织，管理者重点解释差异和作出选择。

### 15.3 每月：能力和资本

每月评审：

- 客户和渠道结构；
- 收入、毛利、现金和预算；
- 关键能力复用；
- Skill ROI；
- 失败和接管；
- 知识过期；
- 组织瓶颈；
- 模型和基础设施成本；
- 应停止的流程、系统和能力；
- 下月资本和人才配置。

### 15.4 每季度：业务和组织重构

每季度回答：

- 市场假设是否仍成立；
- 客户问题是否改变；
- 哪个杠杆正在失效；
- 哪些业务可以扩大；
- 哪些业务应退出；
- 哪些固定系统页面可以被吸收；
- 哪些岗位的工作定义需要重构；
- 哪些能力应成为公司核心 Skill；
- 哪些能力不再产生价值；
- 组织结构是否阻碍 Agent 协作。

### 16.1 第一层：生存和结果

- 现金；
- 收入；
- 毛利；
- 经营利润；
- 应收和库存；
- 客户留存；
- 重大风险；

- 转化；
- 渠道利润；
- Offer 有效性；

- 复购；

### 16.3 第三层：能力引擎

这些指标容易制造控制感，却不能解释经营价值。

## 17. 经营指标与理论公式

### 17.1 企业能力复用率

```text
Capability Reuse Rate
  = 使用已发布能力完成的有效 Work Item
  / 适用 Work Item 总数
```

复用率必须与 Outcome 质量共同观察。低质量能力被大量使用不是成功。

### 17.2 AI 有效采纳率

```text
Effective AI Adoption
  = 被确认且产生预期经营结果的 AI 输出
  / 所有进入正式确认的 AI 输出
```

### 17.3 协调摩擦

```text
Coordination Friction
  = 等待、重复录入、信息寻找、重复确认和跨系统切换时间
  / Work Item 总周期
```

### 17.4 组织学习速度

```text
Learning Velocity
  = 经营事实出现
  -> 形成 Insight
  -> 产生有效 Action
  -> 结果验证
  -> 能力更新
```

衡量的是完整周期，而不是单次模型响应速度。

### 17.5 AI 经营 ROI

```text
AI Operating ROI
  = 有效收入增长
  + 可验证成本节省
  + 避免损失
  + 释放产能价值
  - 模型成本
  - 平台成本
  - 人工确认成本
  - 治理成本
  - 风险损失
```

## 18. 资本配置与 AI

### 18.1 从项目预算转向能力投资

传统数字化预算常按系统项目分配：

- CRM 项目；
- BI 项目；
- OA 项目；
- 数据中台项目；
- AI 助手项目。

AI 原生企业应增加能力投资视角：

- 客户事实能力；
- 项目交付能力；
- 营销实验能力；
- 财务判断能力；
- 供应链决策能力；
- 知识和 Skill 工厂；
- Agent 协作；
- 数据和权限治理；
- 私有化交付。

### 18.2 能力投资门禁

每项能力投资回答：

1. 对应哪个 Business ILPO；
2. 改变哪个经营杠杆；
3. 服务哪些 Work Item；
4. 哪些员工和 Agent 会使用；
5. 预期 Outcome；
6. 需要哪些 Data Product；
7. 风险和人工门禁；
8. 是否可以跨团队复用；
9. 如何评估和停用；
10. 是否减少旧系统和协调成本。

### 18.3 不追求无边界自动化

自动化水平应由以下因素共同决定：

- 结果可验证性；
- 失败可逆性；
- 数据成熟度；
- 风险等级；
- 规则稳定性；
- 人工确认成本；
- 客户和员工信任；
- 法律和责任要求。

自动化不是战略目标，经营结果和组织能力才是。

## 19. 营销、销售、交付和服务的一体化

### 19.1 传统断点

- 营销生产线索但不知道是否成交；
- 销售承诺无法传递给交付；
- 交付问题无法改进产品；
- 服务反馈留在工单；
- 财务只能事后看到利润；
- 品牌不知道真实客户体验；
- 各部门用不同客户口径。

### 19.2 AI 原生主链

```text
Market Signal
  -> Customer Insight
  -> Offer
  -> Campaign / Content
  -> Lead
  -> Opportunity
  -> Commitment
  -> Delivery
  -> Customer Outcome
  -> Revenue / Margin / Cash
  -> Service Evidence
  -> Product / Marketing / Sales Skill Update
```

### 19.3 员工 Agent 的分工

| Agent | 主要执行 |
|---|---|
| 市场 Agent | 信号、竞争、客户问题和机会假设 |
| Creator Agent | KOL/KOC/KOS 发现、Brief、权利和合作效果 |
| KOA / 内容 Agent | 基于品牌和事实生成、本地化、适配和测试内容 |
| Media Agent | 站内、站外、DSP、Open Internet 和预算执行 |
| 销售 Agent | 客户研究、机会推进和承诺检查 |
| Commerce Agent | Marketplace、Social Commerce、DTC 交易和复购 |
| Retail Agent | 零售合作、门店、库存和 Sell-through |
| 交付 Agent | 任务、依赖、风险和交付物 |
| 服务 Agent | 问题处理、知识匹配和升级 |
| 财务 Agent | 利润、现金、预算和账单影响 |

这些不是多套独立应用，而是不同员工 Work Agent 在不同 Task Contract 下加载的
能力组合。

### 19.4 外部承诺

涉及以下内容必须有人工 Owner：

- 价格和折扣；
- 合同条款；
- 交付时间；
- 产品能力；
- 客户数据处理；
- 赔付和退款；
- 品牌公开立场；
- 法律和合规答复。

## 20. 组织内部的 AI 能力市场

### 20.1 能力可以被发现和复用

员工在完成工作时可以发现：

- 已发布 Data Product；
- 正式 Metric；
- 知识资产；
- Team Template；
- Company Skill；
- 可调用 Action；
- 可协作的专家和 Agent。

### 20.2 能力贡献

员工可以提交：

- Knowledge Candidate；
- View Template Candidate；
- Skill Candidate；
- Rule Patch；
- 数据质量问题；
- 流程异常；
- 停用建议。

### 20.3 激励原则

公司可以认可：

- 被验证的能力贡献；
- 跨团队复用；
- 减少错误和摩擦；
- 发现重大风险；
- 改善客户结果；
- 帮助他人提高能力。

不能简单按 Skill 数量、AI 使用量或内容产量奖励，否则会制造能力垃圾。

## 21. Hermes 的对外商业理论

### 21.1 客户真正购买什么

客户不是购买一个聊天窗口，也不是购买更多固定页面。客户购买的是：

- 让每个员工拥有受企业治理的 Work Agent；
- 让员工跨系统完成任务；
- 让经验变成企业知识和 Skill；
- 让 Agent 可以安全协作；
- 让 AI 输出进入正式工作链；
- 让 DTC、Marketplace、Social Commerce、广告、Creator 和线下零售形成全渠道
  Outcome 闭环；
- 让企业保留权限、责任和审计；
- 让已有系统逐步无头化而非一次性重建；
- 让企业能力可以在 SaaS、专属和私有环境运行。

### 21.2 Hermes 与传统 SaaS 的差异

| 传统 SaaS | Hermes |
|---|---|
| 预定义模块和页面 | 动态 Workbench |
| 用户适应系统 | Agent 适应任务 |
| 经验留在用户和流程中 | Evidence → Knowledge → Skill |
| 系统之间依赖集成项目 | Data / Action Contract |
| AI 作为页面功能 | AI 作为员工执行运行时 |
| 统一系统身份 | 员工和 Agent 双身份、明确委托 |
| 版本升级绑定业务能力 | Runtime、Connector、Skill、View 分离升级 |
| 管理看操作 | 管理看 Outcome、Evidence 和例外 |

### 21.3 对客户老板的价值主张

Hermes 帮助老板实现：

1. 不推倒核心系统；
2. 不继续建设大量重复页面；
3. 把员工经验变成公司能力；
4. 把 AI 从个人工具变成正式经营能力；
5. 让组织扩张不再同比增加协调成本；
6. 让营销、销售、交付、服务和经营结果形成闭环；
7. 在保留企业控制权的同时释放员工执行能力；
8. 形成可持续进化的组织智能。

### 21.4 外部表达边界

Hermes 不承诺：

- 消灭所有业务系统；
- 自动替代全部岗位；
- 无需治理即可获得 AI 价值；
- AI 自动作出所有经营决策；
- 一次部署完成组织转型；
- 所有客户获得相同 ROI；
- 模型能力可以替代数据和组织基础。

## 22. Hermes 的长期竞争壁垒

### 22.1 壁垒不只是模型

模型会快速进步，也会被不同供应商提供。Hermes 的壁垒应建立在：

- Work Event Contract；
- Task Contract；
- 双层 ILPO；
- 企业 Business Object 和 Data Product；
- 权限与 Purpose；
- Evidence Graph；
- Knowledge Asset；
- Skill Registry 和 Evaluation；
- Agent Collaboration；
- Outcome 数据；
- 版本、灰度和回滚；
- SaaS 与私有化交付能力。

### 22.2 能力网络效应

企业内部：

```text
更多有效工作
  -> 更多 Evidence
  -> 更好知识和 Skill
  -> 更强 Work Agent
  -> 更高质量工作
```

产品层面：

```text
更多行业实践
  -> 更成熟 Contract 和 Adapter
  -> 更低客户落地成本
  -> 更多客户
  -> 更广行业实践
```

跨客户不能共享客户私有数据。可复用的是协议、匿名化模式、评估方法、行业模板和
Adapter，不是客户业务正文。

## 23. 落地路线

### Stage 0：老板与核心管理层统一心智

交付：

- 公司 Business ILPO；
- 关键经营杠杆；
- 经营红线；
- AI 不可替代的责任；
- 首批 Task Contract；
- 内外部数据边界；
- AI 价值指标。

门禁：

- 核心管理层能用同一语言解释 AI 化；
- 不把 AI 化等同于采购模型或裁员；
- 有明确 Owner。

### Stage 1：建立可信经营事实

交付：

- Business Object；
- Data Product；
- Metric；
- Identity；
- Policy；
- Work Event；
- Evidence。

门禁：

- 经营事实有来源、Owner、版本和权限；
- 关键指标不依赖页面私有逻辑。

### Stage 2：员工 Work Agent

交付：

- 个人 Workbench；
- Task Contract；
- Read Plan；
- 低风险 Action；
- Work Item；
- 人工接管；
- Agent-to-Agent 协作。

门禁：

- 员工可以完成真实任务；
- Agent 不冒充员工；
- 高风险承诺不自动执行。

### Stage 3：外部增长闭环

交付：

- 客户和市场 Data Product；
- DTC+ 客户、Creator、Content、Media、Commerce 和 Retail 对象；
- 营销、销售、交付和服务主链；
- KOL/KOC/KOS/KOA 协作；
- Marketplace、Social Commerce、DTC 和线下零售连接；
- 赢单、失单和客户 Outcome Evidence；
- 首批营销和销售 Skill。

门禁：

- 可以把活动连接到收入、毛利、现金和客户结果；
- 可以识别 L2/L2++ 复购并逐步进入 L4 精准经营；
- KOA 内容受到品牌、事实、版权、预算和人工确认约束；
- 全渠道统一经营事实，不强行统一每个渠道的运营方式；
- 内容产量不作为成功标准。

### Stage 4：内部能力飞轮

交付：

- Knowledge Factory；
- Skill Factory；
- Evaluation；
- Evolution Agent；
- 能力运营；
- 组织激励。

门禁：

- 能力有 Owner、版本、评估和停用；
- 个人经验不会未经确认自动成为公司标准。

### Stage 5：组织和商业模式重构

交付：

- 存量系统 Headless / Absorb / Retire；
- 岗位和团队重新设计；
- 资本配置调整；
- 新产品和服务；
- SaaS、专属和私有化规模交付。

门禁：

- 经营结果改善；
- 协调成本下降；
- 员工和客户信任可持续；
- 风险没有因扩张失控。

## 24. 典型失败模式

### 24.1 只建设一个老板驾驶舱

后果：

- 信息向上集中；
- 员工执行方式不变；
- 数据汇总成本继续存在；
- 老板看到更多，却无法形成组织能力。

### 24.2 只给员工发 AI 账号

后果：

- 经验留在个人；
- 权限和数据不可控；
- 无 Task Contract；
- 无正式 Outcome；
- 无法衡量企业价值。

### 24.3 再建设一个 AI 大中台

后果：

- 新的中央瓶颈；
- 业务等待平台团队；
- Agent 缺少真实工作上下文；
- 重复传统数字化问题。

### 24.4 以监控推动采用

后果：

- 员工隐瞒真实工作；
- AI 反馈失真；
- 知识贡献下降；
- 组织信任受损；
- 系统被动合规而非主动使用。

### 24.5 追求自动化率

后果：

- 人工门禁被视为失败；
- 高风险任务被错误自动化；
- 确认和责任被弱化；
- 错误规模化。

### 24.6 让 AI 生成大量内容

后果：

- 品牌稀释；
- 渠道噪音；
- 客户信任下降；
- 内容和收入脱节；
- 企业形成内容库存而非客户资产。

### 24.7 没有停用机制

后果：

- 错误 Skill 长期存在；
- 模型和规则变化无人负责；
- 人工确认成本不断增加；
- 企业能力库逐渐失真。

## 25. 老板的决策准则

每一个 AI 项目开始前，老板应问：

1. 它改变哪个经营结果；
2. 它服务哪个 Business ILPO；
3. 它利用哪个经营杠杆；
4. 谁承担结果；
5. 输入事实是否可信；
6. 哪些动作必须由人确认；
7. 是否形成可复用能力；
8. 是否减少协调摩擦；
9. 是否增强客户价值；
10. 如何停用和撤销；
11. 是否保护员工和客户信任；
12. 如果不建设新系统页面，是否仍能实现。

## 26. 老板经营宣言

1. 我们不以建设更多系统代表进步。
2. 我们统一经营事实，不统一所有人的工作界面。
3. 我们把执行能力交给员工的 Agent，把经营责任保留在人和组织。
4. 我们以 Task Contract 连接经营选择和 Agent 执行。
5. 我们以 Outcome 和 Evidence 判断价值，不以 AI 使用量判断成熟。
6. 我们把正确经验变成知识和 Skill，让组织能力持续复利。
7. 我们允许员工组织自己的工作方式，但不允许越过数据、权限和责任边界。
8. 我们让管理聚焦目标、杠杆、例外和结果，不监控员工每一个动作。
9. 我们让营销、销售、交付、服务和财务回到同一客户与经营闭环。
10. 我们保留停止、降级、回滚和人工接管的能力。
11. 我们不依赖单一模型、供应商和部署方式。
12. 我们建设的不是 AI 功能，而是一家能持续学习和进化的公司。
13. 我们以 DTC 客户关系为中心连接 Creator、内容、广告、电商和零售，以收入、
    毛利、现金、复购和品牌信任判断全渠道价值。

## 27. 设计结论

### Summary

AI 时代的企业竞争，不只是模型、人才或数据竞争，而是组织把经营洞察转化为有效
动作、再把有效动作转化为可复用能力的速度竞争。

Hermes 将既有双层 ILPO 从中央大一统系统中释放出来：老板和经营 Owner 负责人类
主导的 Business ILPO，Task Contract 把经营选择转为正式执行契约，每个员工的
Work Agent 执行 Execution ILPO，Evolution Agent 再把经过结果验证的实践沉淀为
企业知识和核心 Skill。

### Chosen approach

采用“中央薄治理、边缘厚智能”的 AI 原生组织模式。中央统一目标、事实、语义、
权限、资本、责任和审计；员工拥有自己的 Work Agent 和动态工作台，在明确契约
内组织任务和协作。外部增长飞轮与内部能力飞轮通过客户 Outcome、经营结果和
Evidence 相互驱动。
在外部增长侧，DTC+ 将传播创作者生态、产品与内容营销、电商增长变现和线下零售
组织为统一经营闭环；KOL、KOC、KOS 和 KOA 由员工 Work Agent 在品牌、利润、
库存、客户授权和人工确认边界内协作。

### Open risks

- 企业能否把隐性经营逻辑表达为 Task Contract；
- 管理层能否从过程控制转向目标和例外管理；
- 数据和 Metric 是否具备正式 Owner；
- 员工是否信任并愿意纠正 Agent；
- Skill 评估能否连接真实经营结果；
- 外部营销自动化是否会损害品牌和客户信任；
- 不同行业和企业规模的落地节奏差异；
- AI 收益是否能覆盖模型、治理和组织变革成本。
